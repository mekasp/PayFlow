# PayFlow: інструменти для тестового завдання

Тут лежать допоміжні файли до тестового завдання: приклад подій від платіжного провайдера
**PayFlow** і скрипт, який відправляє ці події на твій сервіс. PayFlow вигаданий,
реєструватися ніде не потрібно.

Умову завдання і документацію webhooks PayFlow ти отримуєш окремо.

| Файл | Що це |
|---|---|
| `happy_path.json` | Приклад послідовності подій для одного рахунку |
| `PayFlowEventsSender.py` | Скрипт, що відправляє події на твій сервіс від імені PayFlow |

## `happy_path.json`

JSON-масив із 9 подій для рахунку `acc_1`: поповнення рахунку, кілька авторизацій,
їх списання і скасування, повернення коштів. Формат кожної події описаний у документації
PayFlow.

Це найпростіший сценарій: кожна подія приходить один раз і в правильному порядку.
Очікуваний баланс і стан авторизацій після прогону цього файлу наведені в умові завдання.

## `PayFlowEventsSender.py`

Відправляє події з JSON-файлу на твій сервіс так само, як це робить PayFlow:
з підписом і повторами при невдачі. Потрібен лише Python 3.9+, сторонніх залежностей немає.

### Запуск

Запусти свій сервіс на `http://localhost:8000` і виконай:

```bash
python3 PayFlowEventsSender.py happy_path.json
```

### Що робить скрипт

Для кожної події з файлу, по черзі й у порядку файлу:

1. Серіалізує подію в JSON (UTF-8).
2. Рахує підпис `HMAC_SHA256(secret, body)` і передає його в заголовку `X-PayFlow-Signature`.
3. Відправляє `POST` на `/webhooks` з таймаутом 10 секунд.
4. Якщо відповідь не `2xx`, повторює спробу кілька разів із паузою.

Для кожної спроби друкує `id` події, її тип, номер спроби, код і тіло відповіді:

```
evt_0001     account.funded           attempt 1: 200 {"status":"ok"}
evt_0002     authorization.created    attempt 1: 200 {"status":"ok"}
...
Delivered 9/9 events
```

Якщо хоча б одна подія так і не отримала `2xx`, скрипт завершується з кодом `1`.

### Параметри

| Параметр | За замовчуванням | Опис |
|---|---|---|
| `events_file` | | JSON-файл з масивом подій |
| `--url` | `http://localhost:8000/webhooks` | Куди відправляти події |
| `--secret` | `whsec_test_123` | Секрет для підпису |
| `--retries` | `3` | Скільки разів повторити невдалу доставку |
| `--retry-delay` | `1.0` | Пауза між спробами, секунди |

### Власні сценарії

Ти можеш створювати свої файли подій у тому самому форматі, що й `happy_path.json`,
і відправляти їх цим самим скриптом.

Скрипт відправляє події послідовно і в порядку з файлу. Справжній PayFlow поводиться так,
як описано в його документації, і саме на це варто розраховувати.
